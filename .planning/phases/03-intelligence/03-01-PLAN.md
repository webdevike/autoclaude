Create PreferencesManager class that stores user preferences at `~/.jarvis/users/{userId}/preferences.json`.

Schema using TypeBox:
- tone: 'concise' | 'detailed' | 'casual' (default: 'detailed')
- verbosity: 'minimal' | 'normal' | 'verbose' (default: 'normal')
- shortcuts: Record<string, string> (max 50 entries)
- behavioralRules: string[] (max 20 items, max 500 chars each)
- defaultMode: string (default: 'personal')
- notificationPreferences: { statusUpdates: boolean, errorAlerts: boolean }

Set `additionalProperties: false` to reject unknown keys.

Implementation:
- Use `Value.Check()` and `Value.Errors()` for validation
- Use `Value.Default()` for applying defaults on load
- Atomic write via temp file + fs.renameSync (POSIX atomic)
- Log size warning if preferences exceed 100KB

Export: PreferencesManager class, UserPreferencesSchema, UserPreferences type

<task type="auto">
  <name>Task 2: Create config tools for preference access</name>
  <files>packages/core/src/tools/config-tools.ts</files>
  <action>
Create two tools for agent access to preferences:

**get_preference tool:**
- Parameters: { key: string } (validates against schema properties)
- Returns current value or "not set (using default)"
- Returns error if preferences not loaded

**set_preference tool:**
- Parameters: { key: string, value: unknown, confirmed?: boolean }
- Validates key against UserPreferencesSchema properties
- If `confirmed` is false or missing, return a confirmation request:
  "I'd like to save preference '{key}' = {value}. Reply 'yes' to confirm or 'no' to cancel."
- If `confirmed` is true, save the preference
- Use validatePreferenceValue() to reject dangerous patterns (shell commands, unknown URLs, template literals)

Export: createConfigTools(preferencesManager: PreferencesManager) function that returns array of tool definitions.

Use TypeBox for tool parameter schemas (consistent with Phase 2 core-tools.ts pattern).
