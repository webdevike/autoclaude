  <name>Task 1: Replace createMinimalResourceLoader with DefaultResourceLoader + extensionFactories</name>
  <files>packages/core/src/pi-session.ts</files>
  <action>
**Root cause:** The current `createMinimalResourceLoader` in pi-session.ts has TWO bugs:

1. **Calls `ext(runtime)` but `runtime` is `ExtensionRuntime`, not `ExtensionAPI`** — `ExtensionRuntime` has `sendMessage`, `flagValues` etc. It does NOT have `on()` or `registerTool()`. Extensions call `pi.on('session_start', ...)` and `pi.registerTool(...)` which fail because those methods don't exist on the runtime object. The catch block swallows these errors.

2. **Returns factory functions, not Extension objects** — `getExtensions()` returns `{ extensions, errors: [], runtime }` where `extensions` is the raw `any[]` factory function array passed in. `createAgentSession._buildRuntime()` expects `Extension[]` objects with `.tools` (Map) and `.handlers` (Map). It gets functions instead, so no tools or handlers are found.

**The fix: Replace `createMinimalResourceLoader` with `DefaultResourceLoader`**

The SDK's `DefaultResourceLoader` has built-in `extensionFactories` support. It uses `loadExtensionFromFactory()` internally (which creates proper `Extension` objects via `createExtensionAPI()`) and returns proper `LoadExtensionsResult` with `Extension[]` objects that have `.tools` and `.handlers` Maps.

In `pi-session.ts`:

1. Add import for `DefaultResourceLoader`:
```typescript
import {
  AuthStorage,
  createAgentSession,
  ModelRegistry,
  SessionManager,
  SettingsManager,
  type AgentSession,
  type ResourceLoader,
  DefaultResourceLoader,  // ADD THIS
} from "@mariozechner/pi-coding-agent";
```

2. Remove the import of `createExtensionRuntime` (no longer needed).

3. Replace the `createMinimalResourceLoader` function entirely:
```typescript
async function createResourceLoader(systemPrompt: string, extensions: any[] = []): Promise<ResourceLoader> {
  const loader = new DefaultResourceLoader({
    systemPrompt,
    extensionFactories: extensions,
    noExtensions: true,   // Skip file-based extension discovery
    noSkills: true,       // We don't use skills
    noPromptTemplates: true, // We don't use prompt templates
    noThemes: true,       // We don't use themes
  });
  await loader.reload();  // This processes extensionFactories into proper Extension objects
  return loader;
}
```

Note: `noExtensions: true` only prevents FILE-BASED extension discovery (scanning ~/.pi/agent/extensions/). It does NOT prevent `extensionFactories` from being processed. The `reload()` method always calls `loadExtensionFactories(runtime)` which processes our inline factories.

4. Update `createPiSession` to use the new async function. Change the `resourceLoader` line:
```typescript
// BEFORE:
const resourceLoader = createMinimalResourceLoader(config.systemPrompt, config.extensions);

// AFTER:
const resourceLoader = await createResourceLoader(config.systemPrompt, config.extensions);
```

This is fine because `createPiSession` is already async.

<task type="auto">
  <name>Task 2: Emit session_start event by calling bindExtensions after session creation</name>
  <files>packages/core/src/pi-session.ts, packages/core/src/agent.ts</files>
  <action>
**Root cause:** The `createAgentSession` function only emits `session_start` inside `bindExtensions()` (line 1351 of agent-session.js) or `reload()` (line 1592). Neither is called after `createPiSession` returns. So even if extensions loaded correctly, their `session_start` handlers (which initialize Exa, Notion, Gmail, Linear API clients) would never fire.

**The fix: Call session.bindExtensions({}) after session creation**

After `createAgentSession` returns, call `session.bindExtensions({})` to trigger the `session_start` event. This fires the extension lifecycle handlers that initialize API clients (Exa, Notion, Gmail, Linear).

In `createPiSession`, after the `createAgentSession` call:

```typescript
const { session } = await createAgentSession({
  model,
  thinkingLevel: "off",
  authStorage,
  modelRegistry,
  resourceLoader,
  tools: [],
  customTools,
  sessionManager: SessionManager.inMemory(),
  settingsManager,
});

// Trigger session_start to initialize extension clients (Exa, Notion, Gmail, Linear)
await session.bindExtensions({});
```

`bindExtensions({})` with empty bindings is safe — it only applies UI context, command context, shutdown handler, and error listener if provided. The important thing is that it calls `this._extensionRunner.emit({ type: "session_start" })` which fires all extension `session_start` handlers.

**What NOT to do:**
- Do NOT try to manually emit events
- Do NOT add extension tool names to the triage prompt — the triage system prompt already knows to delegate "working with integrations (Notion, Linear, Gmail)" and the smart agent will have the tools
