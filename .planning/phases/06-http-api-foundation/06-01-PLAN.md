1. Add `hono` and `@hono/node-server` as dependencies in `packages/gateway/package.json`. Use latest stable versions (hono ^4.x, @hono/node-server ^1.x).

2. Create `packages/gateway/src/http-api.ts` with the following structure:

```typescript
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import type { AgentOrchestrator, Message, StreamProgressEvent } from "@jarvis/core";
import { randomUUID } from "node:crypto";
```

Define `HttpApiConfig` interface:
- `orchestrator: AgentOrchestrator` — the orchestrator instance (same one Telegram uses)
- `port?: number` — defaults to 3457
- `host?: string` — defaults to "127.0.0.1" (localhost only, no external access)

Define the request body type for POST /api/message:
- `sender: string` — user identifier (e.g. "livekit-user" or the iOS user's ID)
- `text: string` — the message text
- `mode?: string` — optional mode override (defaults to orchestrator's active mode)

Define the response type:
- `text: string` — the agent's response text
- `toolsUsed: string[]` — list of tool names used during execution

Create the `startHttpApi(config: HttpApiConfig): Promise<void>` function:
- Create a new Hono app
- Add POST `/api/message` route that:
  a. Parses JSON body, validates `sender` and `text` are present (return 400 if missing)
  b. Constructs a `Message` object: `{ id: randomUUID(), channel: "http-api", sender, text, timestamp: Date.now(), mode: body.mode || orchestrator.getActiveMode() }`
  c. Creates an `onProgress` callback that collects tool names: when `event.type === "tool_use" && event.toolName`, push `event.toolName` to a `toolsUsed: string[]` array
  d. Calls `await orchestrator.handleMessage(msg, onProgress)`
  e. Returns JSON: `{ text: response.text, toolsUsed }` with status 200
  f. Wraps in try/catch, returns `{ error: message }` with status 500 on failure
- Add GET `/health` route that returns `{ status: "ok" }` (useful for LiveKit agent to verify gateway is up)
- Call `serve({ fetch: app.fetch, port, hostname: host })` to start the server
- Log `[http-api] Listening on http://${host}:${port}`

Important implementation notes:
- Do NOT add streaming/placeholder/edit logic like the Telegram path does. The HTTP API is request/response — the LiveKit agent just needs the final text and tool names.
- Do NOT add authentication — this is localhost-only internal communication.
- The `onProgress` callback is the key mechanism for collecting tool names. The claude-code-delegate.ts emits `{ type: "tool_use", toolName }` events during execution. Simply collect them in an array.
- Use `orchestrator.getActiveMode()` as the default mode when `body.mode` is not provided.
