<task type="auto">
  <name>Task 2: Create autonomy tools with confirmation flow</name>
  <files>
    packages/core/src/tools/autonomy-tools.ts
  </files>
  <action>
Create packages/core/src/tools/autonomy-tools.ts following config-tools.ts pattern:

Import Type from typebox, AgentToolResult from pi-coding-agent, scheduler from cron-scheduler, ConfigManager.

Define AutonomyToolContext interface: { cwd: string; currentMode: string; configManager: ConfigManager }

Create createAutonomyTools(configManager: ConfigManager): ConfigToolDefinition[]:

1. add_cron_job tool:
   - Parameters: name (string, pattern ^[a-z0-9_-]{1,50}$), schedule (string), prompt (string, maxLength 500), tier (optional triage|smart default smart), confirmed (optional boolean default false)
   - Validate schedule with cron.validate(), reject if invalid
   - Validate prompt with validateCronPrompt() - reject shell patterns, suspicious URLs, "ignore instructions"
   - Parse with parseExpression to get next 5 runs
   - If !confirmed: return preview with schedule + next runs, ask "Reply 'yes' to confirm"
   - If confirmed: call configManager.addCronJob(), scheduler.scheduleJob(), return success with next run time

2. list_cron_jobs tool:
   - No parameters
   - Return scheduler.listJobs() formatted as list with name, schedule, next run, enabled status

3. remove_cron_job tool:
   - Parameters: name (string), confirmed (optional boolean default false)
   - Check job exists with scheduler.getJob()
   - If !confirmed: return "Remove job '{name}' ({schedule})? Reply 'yes'"
   - If confirmed: scheduler.unscheduleJob(), configManager.removeCronJob(), return success

4. update_mode_config tool:
   - Parameters: key (string), value (unknown), confirmed (optional boolean default false)
   - Whitelist allowed keys: systemPrompt, tone, integrations, statusInterval, cwd (not triage, smart, mode, channels, crons - these need special handling)
   - If !confirmed: return "Update {key} to {value}? Reply 'yes'"
   - If confirmed: configManager.updateModeConfigField(), return success

5. add_tool_shortcut tool:
   - Parameters: shortcut (string, pattern ^[a-z0-9_-]{1,20}$), expansion (string, maxLength 200), confirmed (optional boolean)
   - Uses PreferencesManager.set('shortcuts', {...current, [shortcut]: expansion})
   - Check for existing shortcut, warn if overwriting
   - Confirmation flow as per pattern

6. get_config_history tool:
   - Parameters: mode (optional string), limit (optional number default 10)
   - Call configManager.getConfigHistory(), format as list of commits (hash, date, message)

Include validateCronPrompt() function (from research):
- Reject patterns: /ignore\s+(previous\s+)?instructions?/i, /system\s+prompt/i, URLs to unknown domains, /send\s+(email|message|notification)\s+to/i
- Reject prompts > 500 chars
