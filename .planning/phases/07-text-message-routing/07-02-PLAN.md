In `packages/livekit-agent/src/agent.ts`, add a health check mechanism:

1. **Add a helper function** (near `routeTextToGateway`) that checks gateway health:
   ```typescript
   let gatewayAvailable = false;

   async function checkGatewayHealth(): Promise<boolean> {
     try {
       const res = await fetch(`${GATEWAY_API_URL}/health`, {
         signal: AbortSignal.timeout(3000),
       });
       if (res.ok) {
         const data = await res.json() as { status: string };
         return data.status === "ok";
       }
       return false;
     } catch {
       return false;
     }
   }
   ```

2. **Inside the `entry` function**, before the `dataReceived` listener registration, add a health check with retry:
   ```typescript
   // Check gateway availability
   gatewayAvailable = await checkGatewayHealth();
   if (gatewayAvailable) {
     console.log("[livekit-agent] Gateway HTTP API is available — text routing active");
   } else {
     console.warn("[livekit-agent] Gateway HTTP API not reachable — text routing will retry on each message");
   }
   ```

3. **Update the `dataReceived` handler** (from Plan 01) to include a health check retry if gateway was previously unavailable:
   - Before calling `routeTextToGateway`, if `gatewayAvailable` is false, re-check health:
     ```typescript
     if (!gatewayAvailable) {
       gatewayAvailable = await checkGatewayHealth();
       if (!gatewayAvailable) {
         // Send "not available" message to iOS
         const unavailableMsg = JSON.stringify({
           type: "agent_text_response",
           content: "Text processing is temporarily unavailable. Please try again in a moment.",
           timestamp: Date.now(),
           error: true,
         });
         await ctx.room.localParticipant?.publishData(
           new TextEncoder().encode(unavailableMsg),
           { reliable: true }
         );
         return;
       }
       console.log("[livekit-agent] Gateway HTTP API became available — text routing now active");
     }
     ```
   - After successful `routeTextToGateway`, set `gatewayAvailable = true`
   - In the catch block for gateway errors, set `gatewayAvailable = false` so next message retries health

4. **Add a startup health check with periodic retry in `prewarm`**:
   In the `prewarm` function, after loading integrations and VAD, add a background health check loop:
   ```typescript
   // Start background gateway health check (non-blocking)
   (async () => {
     for (let i = 0; i < 10; i++) {
       gatewayAvailable = await checkGatewayHealth();
       if (gatewayAvailable) {
         console.log("[livekit-agent] Gateway health check passed");
         break;
       }
       console.log(`[livekit-agent] Gateway not ready, retrying in 5s (${i + 1}/10)...`);
       await new Promise(resolve => setTimeout(resolve, 5000));
     }
     if (!gatewayAvailable) {
       console.warn("[livekit-agent] Gateway not available after retries — will check on first message");
     }
   })();
   ```

**Implementation notes:**
- The health check is non-blocking and doesn't prevent the agent from starting or handling voice
- `AbortSignal.timeout(3000)` prevents hanging on unreachable gateway
- The `gatewayAvailable` flag is module-scoped — it persists across room sessions
- On successful message routing, flag is set to true; on failure, set to false for next-message retry
- The prewarm health check loop gives the gateway up to ~50 seconds to become available (useful when both processes start simultaneously)
- Voice functionality is completely unaffected — only text routing depends on gateway
